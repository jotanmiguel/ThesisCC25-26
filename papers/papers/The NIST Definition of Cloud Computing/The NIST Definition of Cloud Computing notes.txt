Essential Characteristics (These five characteristics are considered essential features of cloud computing):
-On-demand self-service.
	Summary: Users can access computing resources whenever they want, without needing help from anyone.
	Simple example: Renting a server or cloud storage with just one click.

-Broad network access
	Summary: Services are available over the internet and can be used on many types of devices.
	Simple example: Accessing your cloud files from your phone, tablet, or computer.
	
-Resource pooling.
	Summary: The provider’s resources (servers, storage, etc.) are shared among multiple customers, but each customer only sees what they need.
	Simple example: Like an apartment building: everyone shares water and electricity, but each apartment is independent.

-Rapid elasticity.
	Summary: Resources can quickly increase or decrease based on demand, almost like they are unlimited.
	Simple example: If your website gets lots of visitors, it automatically gets more capacity to handle them.

-Measured service.
	Summary: Resource usage is tracked and billed based on what you actually use.
	Simple example: Like paying a utility bill: you only pay for what you consumed.


Service Models:
-Software as a Service (SaaS)
	What it is: You use ready-made applications hosted in the cloud.
	Control: You don’t manage servers, storage, or the app itself—only some personal settings.
	Access: Usually via a web browser or app interface.
	Example: Gmail, Microsoft 365, Dropbox.
	Simple way to remember: “I just use the software, nothing else.”

-Platform as a Service (PaaS)
	What it is: You deploy your own applications using tools and services provided by the cloud provider.
	Control: You manage your apps and app settings, but not servers, storage, or networking.
	Example: Google App Engine, Heroku, Microsoft Azure App Services.
	Simple way to remember: “I build and run my apps, but the platform handles the rest.”

-Infrastructure as a Service (IaaS)
	What it is: You rent basic computing resources like servers, storage, and networks.
	Control: You can install and manage operating systems, apps, and some network settings, but you don’t manage the underlying hardware.
	Example: Amazon EC2, Microsoft Azure Virtual Machines, Google Compute Engine.
	Simple way to remember: “I control the OS and apps, the provider controls the hardware.”

Deployment Models:
-Private Cloud
	Definition: Cloud infrastructure dedicated to a single organization.
	Example at FCUL: FCUL sets up its own cloud in the faculty’s data center to host internal systems (like Fénix, research repositories, student databases). Only FCUL members can access it.

-Community Cloud
	Definition: Shared by several organizations with common interests or requirements.
	Example at FCUL: FCUL teams up with other Lisbon universities to create a shared research cloud for storing and processing scientific data (e.g., joint Physics or Biology projects). All participating institutions have controlled access.

-Public Cloud
	Definition: Open to the general public, managed by a third-party provider.
	Example at FCUL: Professors and students use Google Drive, Microsoft OneDrive, or AWS to store files, share assignments, or run virtual machines without needing local infrastructure.

-Hybrid Cloud
	Definition: Combination of two or more cloud types (private, community, or public) that work together.
	Example at FCUL: FCUL uses a private cloud to manage sensitive student data (like grades and enrollment on Fénix), while also using a public cloud such as AWS or Azure for big data analysis in research projects. The two systems exchange data when needed.
