Goal: Overview of the openstack architecture

keytakes: 
	- Widely adopted on the industry;
	- Simple to implement and adapt;
	- Modular, enhancing the previous point;
	- Uses an API (provided by the OpenStack) to communicate between the services
	- OpenStack Components: Keystone (Auth), Neutron (Network), Glance (VM Images), Swift (Image Storage), Ceilometer (), Cinder (Volumes), Horizon (UI), Nova (Virtual Server);

Components:
-Computing
	- Nova (Compute): The core of OpenStack’s IaaS, Nova is responsible for provisioning and orchestrating virtual machines (VMs).
	It interacts with different hypervisors (e.g., KVM, Xen, VMware, Hyper-V) and integrates with Neutron (networking), Cinder (storage), and Keystone (authentication).

	- Glance (Image Service): Openstack Image Service. Manages the catalog of VM images, allowing discovery, registration, and retrieval of images.
	Provides an API to store and manage large libraries of images used by Nova when launching instances.

-Networking
	- Neutron (Networking): Provides “networking as a service” between interface devices managed by Nova.
Supports DHCP, IP address management, VLANs, VPNs, load balancing, firewalls, and intrusion detection.
Its plugin-based architecture allows integration with third-party solutions.


-Storing
	- Swift (Object Storage): Openstack Object Storage. Allows the storage and retrieval of files. Can used to backup the VM modules using Cinder;

	- Cinder (Block Storage): OpenStack Block Storage. Persistent block storage to vm. Cinder will interact with nova, providing volumes.

-Shared Services
	- Keystone (Identity): OpenStack Identity.
 
	- Horizon (Dashboard): Openstack Dashboard. Modular web app for a UI cloud infrastructure management by interacting with the other services public API.

	- Ceilometer (Telemerty): Monitors CPU and Network usage for billing purposes.
	
- Supporting Services
	- Database: MySQL as the default to store configs and management info. Typically runs on the controller node.

	- AMQP (Message Queue): Messaging technology for inter-process communication. A common platform to send and receive messages between them without knowledge of each other's component. 

Conclusions: - Good performance, Reliability and user acceptance; Modular architecture; Simple to implement and adapt for any hardware; Lower running costs, since its opensource;
